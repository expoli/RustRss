# PRD: 缩略图直连口径裁决与远程图片边界验收

## 背景

`47be462` 已交付文章列表缩略图：Media RSS 缩略图优先 → 图片型 enclosure → 摘要/正文首图；随条目落库（旧库迁移时从正文首图回填，全文后取时仅在无既有缩略图时补入）；只接受 HTTP(S)，相对 URL 按条目源地址解析。列表侧由 WebView 延迟加载远程图片、**不发送 Referer**、**不走应用内订阅代理**（`README.md:14`、`manual-verification-checklist.md` §24.24）。

但 `.chorus/specs/rss-reader/spec.md:118` 的验收点写的是：

> 除订阅源地址与用户显式配置的 AI 端点外，应用不产生任何外呼；用代理抓包跑一次完整刷新周期，白名单外请求数为 0

已交付行为与这条验收点**直接冲突**：只要列表里有缩略图，WebView 就会向图片站发起请求，且因为不走应用代理，抓包必然能在白名单外看到它们。不裁决，这条验收点永远无法勾选，也无法判断"到底是功能错还是口径错"。

## 决策（2026-09-24 用户拍板）

把「缩略图由 WebView 直连图片站」写成 spec 的**明确例外**：

- **不做**应用代取（不由 Rust 侧经应用代理拉取图片后喂 WebView）；
- **不做**域名白名单限制（不要求图片站与源同域）；
- 保留现有全局「显示已有缩略图」开关（关闭后该类请求消失）；
- 代价如实写明：**图片站可见客户端 IP 与请求时间**（读者隐私面）。

## 目标

1. spec 与 README 对同一行为给出一致、可验证的表述，取消"零外呼"与"WebView 直连"并存的矛盾。
2. 为「例外之外仍然零外呼」提供一次完整刷新周期的目的地记录（口径可复现，不是口号）。
3. 补齐远程图片的边界证据：公网真实图片源、外站拒绝嵌入、404/超时、离线。

## 非目标

- 不实现应用代取图片（会引入缓存/体积上限/TLS/重定向一整套，将来要做另立变更）。
- 不新增按源或按域名的图片开关（保持单一全局开关）。
- 不宣称"所有图片站都兼容"——公网证据按站点与时间记录，不外推。

## 验收标准

1. `spec.md` 的该验收点改写为可验证表述，含三类允许目的地（订阅源地址 / 用户显式配置的 AI 端点 / 缩略图指向的图片站）与例外说明（不发 Referer、不走应用代理、图片站可见客户端 IP）；`README.md` 与之表述一致；两者不得再出现互相矛盾的措辞。
2. 「白名单外请求数」口径成文：明确订阅源域名、RSSHub 实例（`rsshub://` 解析后的实际主机）、图片站、AI 端点各算什么，并给出记录方式（应用日志/代理记录）。
3. 公网真实 feed 缩略图落地证据：记录站点与时间、库回读 `thumbnail_url`、截图确认列表渲染；同时保留一次本地 fixture 证据作为可复现基线。
4. 外站拒绝嵌入 / 404 / 超时：图片静默失败，不阻塞列表滚动与阅读，无阻塞式弹窗，且**不引起列表行重建或布局跳动**（截图 + 日志）。
5. 离线（隔离网络命名空间，仅 `lo`）：带缩略图的列表可正常阅读与滚动，图片请求失败不影响正文与已缓存内容。

## 风险与缓解

- **公网不可控**：站点会挂、会改防盗链 → 证据注明站点与时间，结论不外推；失败以"当时的观察"如实记录。
- **为迁就旧 AC 而改功能**：明确禁止（用户已选例外口径）；若评审倾向"改功能"必须回到用户重裁。
- **例外被滥用**：口径只覆盖缩略图这一类；其它任何新外呼都必须单独裁决，不得援引本例外。
