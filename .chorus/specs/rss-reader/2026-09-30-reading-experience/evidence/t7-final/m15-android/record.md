## Reproduce

The runnable harness is [verify-reading-experience-t7-m15.py](../../../../../../../scripts/verify-reading-experience-t7-m15.py). It copies the committed 200-row SQLite schema fixture, prepares phase-specific local SQLite files, serves RSS/503 responses from a host-only `ThreadingHTTPServer`, and routes Android emulator requests through `10.0.2.2`. It verifies the AVD name, serial and APK SHA before running. All traffic is synthetic and local; the HTTP port is chosen at run time (33887 in this run). The test uses Android `am start`, HOME, `input tap`, `dumpsys`, `logcat`, app logs, SQLite readback, native screenshots, and CDP only to locate controls/read UI state. Physical taps drive Refresh all and the RSSHub test. The four `*-fixture.sqlite` files plus `fixture.sqlite` retain the exact DB inputs; their hashes are in `results.json` and [SHA256SUMS](SHA256SUMS). Android logcat and notification dumps are byte-preserving gzip files to keep the commit compact.

```bash
avdmanager create avd -n RustRssT7M15 -k 'system-images;android-36;google_apis;x86_64' --device pixel_tablet --force
emulator -avd RustRssT7M15 -port 5586 -no-window -no-audio -no-boot-anim -no-snapshot-save -gpu swiftshader_indirect
adb -s emulator-5586 install -r /home/tcy/Github/RustRss/src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
adb -s emulator-5586 shell pm grant tech.expoli.rustrss android.permission.POST_NOTIFICATIONS
ANDROID_SERIAL=emulator-5586 python3 scripts/verify-reading-experience-t7-m15.py --apk /home/tcy/Github/RustRss/src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk --out /tmp/rustrss-t7-m15-repro
```

System Python 3 with `websockets`, Android SDK `adb`, `avdmanager` and `emulator`, and a free port 5586 are required. The harness uses host Python SQLite because the Android shell's `sqlite3` does not have FTS5; live device SQL only updates settings/timestamps and reads counts. The original failed setup attempt is excluded from these results; all claims above come from the complete `passed: true` run in `results.json`.

## Scope

This verifies the Android emulator artifact and local deterministic feeds, not physical-device delivery, real RSSHub availability, system doze behavior, long-duration periodic reliability, or opening a notification. The 15/120-minute policy was tested with pre-aged rows at the next real 60-second scheduler tick; no 15-minute wall-clock wait was performed. The startup result measures from the `am start` command rather than Activity `onCreate`, so it is an end-to-end bound. The manual negative control asserts unchanged active notification identity as well as the app's single notification emission; it does not infer that the manual refresh failed, since a second unread article was verified.
