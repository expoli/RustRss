# T7 AC5 — native 200-row performance

Task `3bec7638-0f10-4749-b1af-69008bfdb23c`, measured 2026-10-01 on Linux x86_64 (AMD Ryzen 7 7735H, 16 logical CPUs), WebKitGTK 2.52.6 inside a private Xvfb 1400×1000 X11 display. The app used separate `HOME`, `XDG_DATA_HOME`, `XDG_RUNTIME_DIR`, inspector ports, and copied SQLite databases. No user database, Android emulator, or main checkout was used.

## Result

| Build | Source | Binary SHA-256 | 20-click p95 |
| --- | --- | --- | ---: |
| Pre-redesign baseline | `bc680d5155b7c6afcee355fe6aa9bc74ef456031` | `6a2ed07a8479c913457aa782bb8084bc8e02a4e6994e5c5e12e3756d22408284` | 11 ms |
| Final candidate | `1b4c4ca4489f64a2f929838b86bd843e3eb461ce` plus this branch's sidebar no-op-write fix | `39a01543f85edd7542ff7a1a2bb1fa5bd04e091bf6cbe282b3436f71623015e5` | 11 ms |

The candidate exceeded neither threshold: the p95 difference was 0 ms (0%). The gate is a regression only when candidate p95 is **both** more than 20% and more than 16 ms above baseline. P95 uses the nearest-rank 19th value of 20 samples. The baseline and candidate were run sequentially on the same host, WebKitGTK, fixture bytes, harness, and metric. These are one-run measurements, so they do not establish a general performance distribution.

Each app entered the All view with exactly 200 rendered rows. One already-read, image-free row warmed the path; 20 distinct already-read rows were then clicked via DOM `li.click()` in the **native WebKitGTK** app. `performance.now()` measured from click to the matching reader heading and active row mutation after the real handler's `get_entry` IPC. Python inspector transport and polling were outside the timed interval. This exercises production event handlers, IPC, reader rendering, and a 200-node list. It does not measure trusted XTest pointer input, final paint, GPU timing, cold startup, or Android performance.

Across all 20 interactions, every list row retained its DOM node identity and the list had zero child-list mutations; active-class attribute changes were expected. Selecting the current All view again, after interactions, re-ran production sidebar and count rendering with unchanged data. The probe observed `#views`, `#feeds` (including folders), `#tags`, counts, meta, and database path, with attribute, child, and text mutations. All 34 count nodes retained values and identity. The original candidate emitted 47 same-value attribute writes; the fixed candidate emitted **zero** writes in the observed roots. A colored and an uncolored synthetic tag were included, so tag rows were covered. The pre-redesign baseline emitted 18 same-value writes in the final comparison; it is a comparison baseline, not the pass criterion for the candidate.

## Reproduce

Build baseline `bc680d5` and candidate from the fixed branch with `cargo build -p rustrss-desktop`, each in its own worktree and with its own `CARGO_TARGET_DIR` or by saving each binary before the next build. The Tauri binary embeds `ui/` at compile time; rebuilding after a JS edit is mandatory. The measurement script is [verify-reading-experience-t7-performance.py](../../../../../../../scripts/verify-reading-experience-t7-performance.py). Use an available Xvfb binary and a **new** output directory:

```bash
T7_XVFB=/path/to/Xvfb /usr/bin/python3 scripts/verify-reading-experience-t7-performance.py \
  --baseline /path/to/baseline-rustrss-desktop \
  --candidate /path/to/candidate-rustrss-desktop \
  --fixture-source .chorus/specs/rss-reader/2026-09-30-reading-experience/evidence/t7-final/performance/fixture-200.sqlite \
  --out /tmp/rustrss-t7-performance-new-run
```

The runner uses system Python with `websockets`, WebKitGTK's inspector, and `Xvfb -displayfd` to claim an unused display. It starts and stops only its own app and Xvfb processes. `node --check ui/app.js` and `cargo test --workspace` passed in the isolated worktree. The binary hashes above identify the measured artifacts; a later build in another checkout must be measured again before claiming its hash as covered.
