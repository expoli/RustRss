# PRD: 日志终端镜像（调试便利性）

## 背景

日志功能批次（2026-09-22-logging）选择了「结构化 logger + 文件 writer + panic hook」方案，**不含终端双写**：迁移后 `[ui]` 诊断行与 Rust 侧日志只写 `logs/` 下的日志文件，进程 stdout 不再输出。用户反馈：从终端调试（`cargo run -p rustrss-desktop`）时看不到日志，不方便。本变更恢复终端可见性，同时保留文件日志的全部能力。

细化已确认：触发条件 = **检测 stdout 是否为终端**（`std::io::IsTerminal`），并支持环境变量 `RUSTSS_LOG_STDOUT=0/1` 强制覆盖（无头/脚本场景用 `1` 开启）；镜像统一写 **stderr**（不污染 stdout）。

## 需求

### FR-1 终端镜像判定

- 判定规则：`RUSTSS_LOG_STDOUT=1` → 开；`=0` → 关；未设置或非法值 → 用 `stdout().is_terminal()` 的结果；
- 判定在启动时做一次（不随运行期变化）；
- 判定逻辑必须可测（不依赖真实 TTY：把「TTY 探测结果」与「环境变量值」作为输入的函数）。

### FR-2 镜像输出

- 镜像开启时：每条**通过级别与 target 过滤**（与文件同一判定）的日志行，以**与文件行完全相同**的格式（时间戳/级别/target/消息）**追加写 stderr**；
- 镜像关闭时：不产生任何终端输出（桌面启动/启动器场景无多余输出）；
- 镜像行不是额外数据源：不得改变文件日志的内容、顺序、级别语义与保留策略。

### FR-3 文档与测试

- README 日志章节补充终端镜像说明（如何从终端看日志、`RUSTSS_LOG_STDOUT` 用法、镜像与文件行同源）；
- 单测：判定函数真值表（env 覆盖/TTY 组合/非法 env 值回退）；writer 镜像输出内容与文件行逐字节一致（或结构等价的解析比较）；镜像关闭时无 stderr 输出；
- 回归：文件日志（每启动一份、保留 20 个 / ≤50MB、scrub、target 过滤）行为不变。

## 验收口径（行为级）

1. 从终端运行（stdout 是 TTY）：日志行同时出现在终端 stderr（含 `[ui]` 行、启动行），内容与本次日志文件一致；
2. 重定向到文件运行（stdout 非 TTY）：默认**无**镜像输出；`RUSTSS_LOG_STDOUT=1` 时镜像出现（给出命令与输出片段）；
3. 桌面/启动器启动：无额外 stderr 噪声；
4. 文件日志行为与改造前一致（保留策略与内容不变，有回归证据）；
5. `cargo test --workspace` 全绿 + `cargo clippy --workspace` 无新增警告。

## 范围外

- 设置页开关（已决策：不做设置项，只用 TTY 检测 + 环境变量）；
- 彩色/分级着色、终端进度条等格式化增强；
- 把日志接到系统日志（journald/syslog）。
