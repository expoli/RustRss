# PRD: 本机可测验收收口批次

## 背景

一批功能已实现但缺证据：spec 里对应条目仍开放，`manual-verification-checklist.md` §24.x 已记明边界（哪部分是 Xvfb、哪部分需要原生会话、哪部分依赖外部软件）。这些开放项混在主题/网络/搜索/键盘四条线里，长期处于"做了但不敢勾"的状态，既无法判断剩余工作量，也容易在后续改动中悄悄退化。

本变更把**本机可闭环**的部分一次收干净，剩下的明确标成环境依赖，不再与"待办"混在一起。

## 范围

1. **键盘主流程（含实现）**：上下移动 / 打开 / 返回 / 切换视图 / 搜索 / 标记已读 / 刷新 / **全部标记已读** 的完整串联。
   - 现状：`?` 帮助与侧栏行键盘焦点已补齐；**已验口径**为 Xvfb + xdotool 注入串联（清单 §24.20 记 12 项、`keyboard-search.md:19` 记 13 项断言，两份数字不一致——执行时以 `keyboard-search-results.json` 为准并统一口径）。
   - **缺的实现**：`ui/app.js` 的 `onGlobalKeydown` switch 没有「全部标记已读」键（`markAll()` 目前仅 `app.js:4397` 菜单可达），需新增快捷键 + `?` 帮助清单 + `ui/i18n.js` 文案（zh-CN / en）。
   - 待验：全部标记已读 + 刷新 + 各标志操作的串联。
2. **搜索端到端**：WebView 输入 → 列表渲染的端到端证据；10k 篇库的「即时」验收在 **release 构建**口径复测（现有 16–18ms（单字）/ 65–77ms（宽泛）为 core 测量口径，不可直接代替）；原生 Wayland 会话下的搜索输入。
3. **离线与外部图片**：隔离网络命名空间下已抓取文章可读、刷新失败可继续导航（计数口径漂移：`search-offline.md:41` 记 16 项、清单 §24.21 记 15 项——执行时以 `offline-namespace-results.json` 为准，并把两份文档口径统一）；补外部图片（缩略图）离线表现——与 `2026-09-24-thumbnail-egress-policy` 共享同批实例证据，不重复造。
4. **剩余错误码 / 双语文案本地化（含少量实现）**：按清单现成锚点枚举未覆盖范围——**系统真实 DNS、其它 TLS 错误（非自签名）、代理、Retry-After 后台退避、原始后端错误详情、其它产品错误路径**（§24.15 末条 + §24.16 末条）；保持 zh-CN 与 en 的 key 集合一致。
5. **HTTPS 代理本地夹具**：本机能做的最小证据（本地 CONNECT 隧道成功路径）；企业证书 / 认证代理如实标为外部依赖。

## 依赖与串行（Round 1 B1 修复——把散文约束升级为机器可读的 DAG）

调度约束必须写进任务依赖与任务正文，不留在 PRD 散文里（「机制优先于提示词」）：

| 边 | 理由（文件级对照） |
|---|---|
| **T1 → T2** | T2 是搜索端到端取证，可能需修搜索输入路径；证据必须对应含 T1 改动的最终树，避免“收口证据取自中间树” |
| **T1 → T4** | T1 改 `ui/app.js`（onGlobalKeydown）+ `ui/i18n.js`（帮助文案）；T4 必然新增 `ui/i18n.js` 错误文案 key 并可能改 `app.js` 错误渲染路径——同 cwd 并行写这两个文件会相互覆盖、i18n key 集一致性测试变红 |
| T3 独立 | 只读取证（离线/图片/代理），不改 `ui/` 代码 |

**为何不用 worktree 并行**：本批以 GUI 取证为主，worktree 要付一份完整 `target/` 重建（实测单份 debug target 38G，主盘可用仅 49G），且桌面端单实例（D-Bus 名由 bundle identifier 派生）不允许两个界面共存——并行写只会把省下的资源再花回去，并制造脏树证据。

**文件所有权**（写入任务正文）：T1 独占 `ui/app.js` + `ui/i18n.js`；T4 在 T1 之后才写这两个文件；T2/T3 不改 `ui/`，只读与取证。

## 验收标准

每条开放项**二选一，禁止空勾**：

- (a) 给出「复现命令 + 产物路径 + 时间」的证据，并勾选 spec 对应条目；
- (b) 降级为环境依赖，写明缺什么环境（OS / 会话 / 硬件 / 第三方服务），并保留为 open。

补充口径要求：

1. 证据文件落 `.chorus/specs/rss-reader/2026-09-24-local-acceptance-closeout/`，每条附结果 JSON 或截图，文件名与条目对应。
2. 键盘与搜索项必须在**真产物**上验证（前端改动后先 `cargo build` 再跑，见项目红线 #10）；性能数字必须标注构建类型（debug/release）与缓存状态（冷页/热缓存）。
3. 隔离实例沿用既有配方（`HOME` / `XDG_DATA_HOME` / `XDG_RUNTIME_DIR`，参照 `scripts/verify-*.py`）。
4. 本地化部分：`cargo test --workspace` 全绿，i18n key 一致性测试覆盖新增文案；界面无硬编码文案。

## 非目标

- 不用 Xvfb / 当前 KDE 结果代替 GNOME、无 XWayland、Windows、macOS、输入法、读屏器、分数缩放——这些保持环境依赖并如实标注。
- 不做无关重构；不把性能测量从 core 口径扩到"所有查询"。

## 风险与缓解

- **批次过宽变成"永远差一点"**：按 3–4 个任务拆，每个任务以「证据文件路径」为交付物。
- **假阳性**：只看截图不算证据 —— 关键路径要求库回读/日志同时自证。
- **资源冲突**：GUI 单实例（`tech.expoli.rustrss.SingleInstance` 由 bundle identifier 派生）与 target 构建锁是独占资源 → 本批次与相邻变更的 GUI 取证合并到同一时段，cargo 命令串行。
