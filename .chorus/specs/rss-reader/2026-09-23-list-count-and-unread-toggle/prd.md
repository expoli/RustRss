# PRD: 列表计数口径 + 只看未读入口 + 大数据量加载兜底

## 背景

用户在界面上看到列表头右侧显示「200 篇」，把它理解成了当前视图的文章总数（库里实际是未读 13237 / 全部 13312），于是提出三问：这个数是什么、要不要优化、能不能加载全部文章、是不是该加「只看未读」。

核对现状后确认三件事：

1. **头部的「200 篇」是「已加载」而不是总数**（`ui/app.js:742-751`：`listCountN()` 取 `state.entries.length`，未读视图只数其中仍未读的行；全库总量其实在左下状态栏 `{db.entries} 篇 · 库路径`，`ui/app.js:651-653`）。
2. **全部文章已经能取到**：滚到底自动续批，200/批，keyset 游标（`(sortkey, id[, read])`），无重复无跳条，加载完匹配集即停（清单第 69 条已验收；`ui/app.js:1859-1912 / 2050-2135 / 855-880`）。搜索是一次性 200 条、不续页。
3. **「只看未读」功能已存在**：列表头排序菜单里的「隐藏已读」，全局设置 `list.hide_read`、跨重启保留，星标/稍后读视图豁免、搜索不豁免（清单第 70 条已验收；`ui/app.js:2005-2015`、`commands.rs:766-777`、`store/mod.rs:991-1007`）。问题是入口埋在排序菜单里——**用户本人（本仓作者）都没找到它**，这本身就是交互证据。

另有一处风险：**列表没有任何加载上限**，13k 未读一路滚到底会把全部行灌进 DOM，属于仓库红线 #6（「200 行全量重建引起 CPU 风暴」）的同类风险。

结论：① 入口要放在列表/工具栏显眼处，或做成 per-feed 记忆；② 「读完立刻消失」两派都有代价，NNW 派与本仓现状一致；③ 未读计数避免全表 `count(*)`——本仓的总数已是覆盖索引查询，缺的只是**显示**。

## 需求（本次交付）

### 1. 计数口径：区分「已加载」与「总数」

- 列表头显示 `已加载 M / 共 N`；未读视图（或开启「隐藏已读」后的等效筛选）显示 `已加载 M / 共 N 未读`。
- `N` 必须是**当前视图有效筛选下的真实总数**，来源全部是索引计数：智能视图取 `counts()`（未读/全部/星标/稍后读），源/分组/标签维度取侧栏已有的未读计数与补充的总数查询。
- 搜索视图（FTS）本批不查总数，只显示「已加载 M 篇」。
- 续页进行中与哨兵处显示进度（`已加载 M / 共 N`），让用户知道自己在结果流的哪个位置。

### 2. 「只看未读」提到明处

- 列表头增加**常驻可见**的「只看未读」开关，复用现有全局设置 `list.hide_read`（不新增设置键）；默认关，升级后行为不变。
- 排序菜单里的旧入口保留打勾状态（两处同步同一设置）。
- 增加一个快捷键（如 `U`）切换，并在快捷键自检清单里登记。
- 星标 / 稍后读视图的豁免语义保持不变。

### 3. 大 backlog 的手动兜底

- 保留自动续批（IntersectionObserver 哨兵）不变。
- 哨兵行在**没有请求在飞**时显示可点的「加载更多」按钮（进度一并显示），供自动续批未触发或续页失败后恢复时使用。
- 不设行数上限、不做虚拟列表（见非目标），但要在界面上如实给出进度，让用户能自行决定是否收窄视图。

## 非目标

- 不做虚拟列表/窗口化渲染（工程量大，收益留待真实卡顿证据）。
- 不做「加载 2000 行后截断」的硬上限（本批只给进度与手动入口）。
- 不做 per-feed 记忆的只看未读（Feedly 口径，需要新增 per-feed 状态与迁移）。
- 不改「标记已读后立即从列表移除」的语义（保持灰显、重建时离开）。
- 不实现「当前视图」scope 的「全部标记已读」（清单第 79 条遗留，另开一批）。
- 不为搜索视图计算 FTS 总数。

## 验收点

- [ ] 列表头在未读/全部/星标/稍后读/单源/单分组/单标签视图下显示 `已加载 M / 共 N`，`N` 与侧栏/状态栏的同一口径数字一致；搜索视图显示 `已加载 M 篇`。
- [ ] 续批过程中 `M` 单调递增且不超过 `N`；`N` 不因续批而变（同一视图内稳定）。
- [ ] 取数复用优先（源/标签总数复用现成查询）；新增的分组总数查询有 EXPLAIN 断言（走覆盖索引、无裸 `SCAN entries`）并带变异校验（去掉索引时测试变红）；未读口径不得改成裸 join `entries.read`。
- [ ] 列表头「只看未读」开关常驻可见、点击立即重查重渲（reset 语义）、与排序菜单里的勾选同步、跨重启保留；快捷键可切换且登记进快捷键自检。
- [ ] 哨兵行在空闲时可点击加载下一页，显示 `已加载 M / 共 N` 进度；续页失败后仍可通过它重试（不再是「只能换视图恢复」）。
- [ ] 滚动到结果末尾时给出明确终止态（无哨兵/无按钮），不误导为「还有更多」。
- [ ] 既有行为不回归：清单第 69/70 条的分页不重不漏、隐藏已读豁免规则、后台刷新 prepend/静默语义全部保持。
- [ ] i18n 双语（zh-CN + en）齐备，key-set 一致性自检通过；README 与清单第 69/70 条按要求回填。
