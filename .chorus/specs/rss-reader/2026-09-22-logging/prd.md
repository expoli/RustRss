# PRD: 日志功能

## 背景

用户反馈问题时缺少可用的诊断材料：现状 Rust 侧用 `println!/eprintln!`（无时间戳、无级别），UI 侧诊断行（`[ui] ...`）只进进程 stdout——只有从终端启动才看得到，普通用户拿不到任何日志。本批次提供「每次启动一个日志文件 + 一键打开日志目录」，让用户能把日志发来定位问题。

细化阶段已确认的 4 个决策：结构化 logger + panic hook；保留最近 20 个文件且总量 ≤ 50 MB；关于页提供「打开日志目录」按钮；提供 `log.level` 设置项（info/debug）。

## 需求

### FR-1 每次启动独立日志文件（结构化）

- 应用每次启动创建独立日志文件，文件名含启动时间，落在数据目录 `logs/`（跟随现有 `paths::default_data_dir()`）；
- 行格式含本地时间戳（毫秒）、级别、来源模块（如 `2026-09-22T23:45:01.123 INFO  rustrss_core::fetch: ...`）；
- 覆盖 Rust 侧关键事件（现有 `println!/eprintln!` 全部迁移）与 UI 侧诊断行（现有 `[ui]` 日志写入同一文件）；
- **panic 写入日志**（含 payload 与位置），保留既有 stderr 行为。

### FR-2 保留策略

启动时清理：只保留最近 20 个日志文件，且总量 ≤ 50 MB；超限从最旧的删（两条上限独立生效，先满足字节上限再满足数量上限）。

### FR-3 设置 → 关于：「打开日志目录」

在「关于」页提供按钮，用系统文件管理器打开 `logs/` 目录（不内嵌日志查看器）；路径作为独立进程参数传给系统启动器，**不经 shell 解析**（延续外链打开的安全硬化口径）。i18n 双语。目录不存在时先创建；打开失败给出可读错误而不是崩溃。

### FR-4 日志级别设置项 `log.level`

设置项（info / debug，默认 info），非法值回落 info；切换**即时生效**（无需重启）。debug 记录更详细的内容（如 HTTP 请求细节），便于用户复现问题后提供日志。设置页新增控件 + i18n 双语。

## 非功能要求

- **敏感信息绝不落日志**：AI API key、MCP token 等（沿用并复核现有 scrub 口径，迁移点逐个审查）；
- `rustrss-core` 不依赖 Tauri（日志实现放 core，`log` 只是门面）；
- 不引入 UI 构建链；依赖最小化（`log` 门面 + 已有 `chrono`）；
- 跨平台（Windows/macOS/Linux）行为一致；
- **日志写入失败不得影响应用运行**（初始化失败降级为无日志，不崩溃、不阻塞启动）；
- 保留清理逻辑幂等、可测。

## 验收口径（行为级）

1. 启动后 `logs/` 出现以启动时间命名的日志文件，内含启动行、`[ui]` 诊断行与带时间戳/级别/模块的错误行
2. 触发 panic 时，日志文件中有 panic 记录（payload + 位置）
3. 预置 25 个日志文件或总字节超 50 MB → 再次启动后剩余文件同时满足「≤20 个」与「≤50 MB」
4. 关于页点「打开日志目录」→ 系统文件管理器打开该目录；无文件管理器环境（如 Xvfb）给出可读错误提示且不崩溃
5. `log.level=debug` 后出现 debug 级日志行；改回 info 后 debug 行不再出现（即时生效，无需重启）
6. 日志文件中不含 API key / MCP token（含测试或逐点审查证据）

## 范围外

- **便携模式（程序同级 `data/`）**：该能力当前未实现（durable spec 中为未完成项，`paths.rs` 无便携分支）；未来落地后日志目录会随 `default_data_dir()` 自然跟随，本批不实现、不测试该路径
- 内嵌日志查看器、日志搜索/过滤 UI
- 远程上报 / 遥测 / 崩溃收集服务
- 结构化 JSON 输出、日志压缩、按大小滚动（rolling）
- MCP server 二进制的独立日志初始化（后续可复用本批 core 设施）
