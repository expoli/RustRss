# Android 诊断日志查看与导出 — PRD

## 背景与问题

2026-10-01 排查安卓端「121 个订阅刷新停在 4/121、报告只剩 4 个结果」时确认：任务级 panic
只落在设备沙盒的日志文件里（panic hook 以 error 级写入 `logs/rustrss-*.log`），而 release
APK 非 debuggable、`adb run-as` 不可用，用户拿不到日志，排障只能靠代码推演。

日志基础设施已经存在（`rustrss-core/src/logging.rs`：每次启动一个文件、保留 ≤20 个、总量
≤50MB、写入口径 scrub），缺的只是「用户在设备上看到并取走它们」的口子。

## 目标

Android 用户（及协助排障的开发者）无需 adb/root，即可在应用内：

1. **列出** `logs/` 目录下全部 `rustrss-*.log`（prune 保留的 ≤20 个），看到名称、大小、
   修改时间，并明确哪个是本次启动的当前日志；
2. **查看** 任一日志内容：默认只加载文件末尾 256KB，超出时给出明确的「已截断」提示
   （排障最关心的最新内容——包括 panic 行——恰在尾部）；
3. **导出** 任一日志为完整文件：走系统文档选择器（CREATE_DOCUMENT）保存到用户自选位置，
   与 OPML 导出同一条已验证链路。

## 需求

- 入口位于 设置 → 数据 分类内新增「诊断日志」块（与 OPML 导入导出/备份同区，不新增分类）；
- 日志列表最新在前；每项提供「查看」与「导出」两个动作；提供「刷新」重新扫描目录；
- 查看区超出 256KB 时必须在界面上明示「已截断，仅显示末尾」，不得让用户误以为看到了全文；
- 导出成功提示落点、用户取消有对应提示、失败给出可读错误（与 OPML 导出三态一致）；
- 桌面端不出现该入口（本轮 Android 专属）；命令层跨平台编译，不设 cfg 墙。

## 验收标准

- [ ] 设置→数据出现「诊断日志」块：列表含名称/大小/修改时间/「当前」标记，最新在前，可刷新；桌面不显示该块（AC1）
- [ ] 点「查看」默认加载末尾 256KB 并渲染为只读文本；文件超限时界面出现截断提示（AC2）
- [ ] 点「导出」拉起系统保存对话框，完成后提示保存位置；取消返回有对应提示；失败展示错误（AC3）
- [ ] 文件名守卫：仅接受 `rustrss-*.log` 形态，含路径分隔符或其它名字的请求被拒（core 单测钉住）（AC4）
- [ ] `cargo test --workspace` 全绿；`cargo clippy --workspace --all-targets` 无新增告警；i18n key-set 一致性测试绿（AC5）

## 非目标

- 日志删除/清空（prune 已自动清理）；
- 日志级别切换 UI（`log.level` 设置已存在）；
- 桌面端 UI 入口；
- 日志结构化/检索/过滤。

## 隐私与安全口径

- scrub 纪律在**写入口径**执行（各落盘调用点过 `scrub_log_line`），查看/导出**原样输出文件
  内容**，不做二次加工——文件内容即最终脱敏口径，二次 scrub 反而可能破坏行完整性；
- 导出目标是用户显式选择的私有位置，属用户自主行为；
- 读取接口按文件名白名单守卫，杜绝路径穿越。
