# RustRss v0.3.1 发布验证（2026-10-01）

产品提交与 annotated tag：`f4f3b1edb9649737a4f15aa3371324e9d7341420` / `v0.3.1`。
[GitHub Release](https://github.com/expoli/RustRss/releases/tag/v0.3.1) 为正式公开版本，
三份附件均从同一 tag 源码生成，并已实际下载、与 GitHub 资产官方 SHA256 digest 逐一核对一致
（首轮下载两次遭遇网络截断，字节数不符即重下，最终三份全部与 digest 吻合）。

v0.3.0 的 release 工作流因 Windows NSIS 构建失败（webview2-com / windows-core 跨版本类型混用）
未产出发布，本版是 0.3.x 线首个正式发布，覆盖 v0.3.0 全部功能与 v0.3.1 的发布工程修复：

- 统一 Windows 预览截图与 Tauri/Wry 的 WebView2 COM 依赖线（`webview2-com` 0.39 / `windows` 0.62 /
  `windows-core` 0.62 同线，`windows-core` 保留为直接依赖——`#[implement]` 宏展开按本包 extern
  prelude 解析 `::windows_core::…`，删除即 CI 复红，e14bbe5 修复并经 windows-check 验证）。
- Tauri 钉在 2.12.x 次版本线；CI 新增 Windows 专属库编译与版本一致性检查（workspace /
  tauri.conf.json / release tag / Android versionName-versionCode）。

验证链路（同打 tag 前的 preflight 顺序）：

- 提交 `e14bbe5` 的 [CI](https://github.com/expoli/RustRss/actions/runs/36877077924)
  （test / clippy / windows-check）与 [Android CI](https://github.com/expoli/RustRss/actions/runs/36877077835)
  均成功；Android CI 对 debug 通用 APK 做了 versionName/versionCode 一致性与 apksigner 校验。
- [Preflight（workflow_dispatch）](https://github.com/expoli/RustRss/actions/runs/36878070211)
  在 `217123e` 上三平台打包全绿（validate + Linux deb / Windows NSIS / macOS dmg）。
- [正式发布工作流](https://github.com/expoli/RustRss/actions/runs/36880358191)
  的版本校验（--expected 0.3.1）、三平台打包与 Release 创建均成功。
- Linux deb 内部版本 `0.3.1` / 架构 `amd64`（dpkg-deb 核对）。
- Android APK 在本机从 v0.3.1 tag 的产品源码（worktree `217123e` + 原发布密钥）release 构建：
  versionName `0.3.1` / versionCode `3001`，minSdk 24（Android 7.0+），ARM64 + x86_64 通用包，
  非 debuggable，v2 签名证书 SHA256 `89269c116afaa9ca546f7287b268f00c14d5598b6c633715a74fbbcd28de8cc5`
  与 0.1.0 / 0.2.x 发布包同钥，可覆盖安装；`check-version-consistency.py --apk` 与
  `apksigner verify` 均通过，上传后回程下载哈希与 GitHub digest 一致。

边界：macOS arm64 dmg 仍未签名，首次打开需右键→打开。Windows/macOS 安装包已编译并下载核对哈希，
但原生启动器、系统托盘、WebView2 截图等安装后运行行为未在本轮实机重新验收。0.3.0 的 v0.3.0 tag
仍存在（指向 `424c158`），但其 Release 不存在，v0.3.1 的 compare 链接覆盖两版全部变更。

Android 覆盖升级运行时验收（2026-10-08 补）：API 36/x86_64 模拟器上先装正式 0.2.1（安装后
SHA256 与发布资产一致），URL 添加两个真实订阅（宿主机 HTTP server，真实抓取解析落库）后
`install -r` 升级 0.3.1：UID 不变（10229）、两条订阅与全部 3 条条目保留（root sqlite3 回读）、
Launcher 图标启动、热启动 IME 不遮 URL 输入框、设置分类页正常。OPML 选择器自动化本轮未走通
（该功能以 v0.2.1 发布轮证据为准）。步骤、截图与结果见 [Android 证据](v0.3.1-android/README.md)。
